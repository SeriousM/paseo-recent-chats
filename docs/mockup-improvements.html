Baseline: the list stays a list. Sections, rows, the ⋮ menus, pins and read marks keep working as today. Every change below is either a smaller row, a shortcut to something the ⋮ menu already does, or a settings-page cleanup.

1

First row: fewer buttons, one overflow medium

Today the row holds the view switch, Hosts, Add project, Search, Settings, counts and back/forward. Keep the switch, Search and the counts; move Hosts, Add project and Settings into one ⋯ menu. Show all three counts (waiting red, finished green, running blue) like the Paseo row does. Same functions, half the width; the phone row then fits without the icon-only switch.

2

Answer a permission from the row highneeds API check

A Needs you row that waits for permission shows what it asks (tool and command, one muted line) and Deny / Allow. A question keeps Open to answer (the row's own tap). The list's whole job is "what needs me"; this answers the most common case without leaving the list. Only if Paseo's plugin API lets us respond to permissions; otherwise skipped.

3

Pinned chats: pin as a mark, not a button medium

The unpin button costs a 20 px column on every pinned row. Show the pin as a small mark before the title and keep Unpin in the ⋮ menu. Titles get the room back, rows line up again; nothing is lost (Unpin is one click away).

4

Say what a filter hides medium

When "Last 14d", Hosts or search hides something, one line under the filter row says how much and offers show them. Today a hidden workspace just isn't there, which reads like a bug (the "Every host is switched off" report).

5

Running chats tick low

A running chat shows how long its turn has run (2:41), updated every second, instead of a fixed age. The workspace light turns blue while one of its chats runs. Answers "is it stuck?" at a glance; uses data we already have (turn start).

6

Quiet projects: a fold, not a sentence low

"4 quiet projects: AzDevOps, collector…" becomes a fold row like the others (▸ 4 quiet projects). Consistent with every other fold; the names are visible once opened.

7

Phone rows: title first, actions in the menu or a swipe high

On a phone the 32 px read and pin buttons leave the title ~12 characters. Put the project under the title (second line), keep only ⋮ on the row, and mark read with a swipe left (Later with a swipe right), the same as Paseo's own lists. Line changes shorten to 99.8k. The title is what you scan for; the row stays one tap to open.

8

Touch or mouse, not phone or desktop medium

Decide button sizes, hover and drag handles by the input (coarse pointer, hover), not by the narrow layout. A touch laptop gets thumb-sized targets; an iPad with a trackpad gets hover. Paseo 0.16.1 fixed exactly this in its own UI; our grip and drag trouble came from guessing by width.

9

Tabs, dimmed dependents, reset per tab high

The one long page becomes four tabs. An option that depends on a switch is dimmed while that switch is off (After Later, card transparency, phone height). Each tab can be reset, with a second press to confirm. Same settings, findable; nothing new to learn.

10

One preview that stays in view medium

On a wide window the preview sits beside the options and stays put while you scroll; on a narrow one it sits above them. A Desktop / Phone switch draws the same rows at phone width. Today's three separate previews (row layout, Projects, card) merge into it. You see the effect of a change without scrolling back up.

Left out on purpose

These are Better Paseo's core, not a list's job, so they stay out:
  • A Tasks board with lanes, cards, card density, lane width and a details sidebar.
  • Redrawing the chat timeline, tool icons, reply styles, image viewer, find bar.
  • Automatic chat titles, usage and cost charts, token rings.
  • A second language. Possible later, but not a list improvement.
Smaller things that fit but can wait: keyboard keys (J/K, Enter, /, Esc), rows that slide between sections instead of jumping (off under reduced motion), and a "Known limitations" page listing what Paseo does not let plugins do (pill order, drawer height, switching the sidebar view).
